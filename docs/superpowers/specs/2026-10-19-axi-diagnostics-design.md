# AXI等待分解：性能选择门

目标是提高相同Alpha/Key工作量下的稳定60FPS活动Sprite上限。上一轮Alpha只带来普通512平均work约0.525%的改善；1040分段背景约5.56ms、Key约3.55ms。现有stalls不统计R无数据或B未返回，不能直接据此决定双在途写。

本轮先实现默认关闭的诊断，不把计数器本身当性能提升。官方Sapphire、CPU基础绘图、100MHz、DDR、HDMI、网口、灰度/缩放、原命令和资格规则不改。只JTAG/RAM，不写Flash、不推送、不替换release。板卡COM9/COM15可见时才尝试加载，先仿真和最终时序检查。

## 接口与定义

`--axi-diagnostics` / `enableAxiDiagnostics=false`仅在候选增加APB页0x0600，STATUS bit19声明能力。旧BIT/默认生成不存在该页。页内ID为0x41585046；0x0604 CONTROL低bit0启用、bit1清零，保留位或只读寄存器写入报错且无副作用。0x0610开始16个只读32bit计数，顺序：

0 W握手，1 W事务内数据未供应，2 WVALID且物理WREADY低，3 WLAST后BVALID低，4 AW物理背压，5 AW因显示紧急状态无法新准入，6 物理R握手，7 已准入读事务RVALID低，8 物理R响应因缓冲不接收，9 AR物理背压，10 AR因显示紧急状态无法新准入，11 Render AR等待完整响应缓冲空间，12 Render B握手，13 Render AW握手，14 Render端R有效但消费者未接收，15 启用窗口总周期。

只统计Render，不混入Scanout/Asset事务；Key读取的列表描述符属于Render，必须标注。0/6计实际32bit总线拍，包含零WSTRB写拍，不是有效像素字节。不同通道可重叠，不能把所有计数相加解释成总耗时。3是总B尾等待上界，不自动等于可隐藏收益。计数模2^32，独立阶段必须小于42秒（100MHz），停止后读取，不宣称全程CPU占用率或物理DDR带宽利用率。

`DdrQosArbiter`在显式诊断开关下输出16个事件，不插入握手寄存器、不修改准入或VALID/READY。`AxiDiagnosticRegs`复用现有APB setup/transfer约定，CONTROL清零优先于当拍计数。Top候选接入现有响应级；默认不实例化寄存器和事件逻辑。

## 验证与取舍

先真实Chisel测试事件归属、延迟B和空R（而非mock计数器），APB冻结/清零/非法访问，Top能力与路由。只运行一次最终GPU全套，修正只复测受影响套件；既有两项SoC异常保持独立。生成split-verilog，一文件一模块，最终全部时序关系为正才上板。

`test_board_sprite_phases.c`用显式构建参数启用诊断，保留原默认BIN行为。沿用相同512/1040、tick11/22/33、原顺序FULL与像素/错误规则，每阶段开始清零并启用，结束先停止再读计数，串口在计量之外。固定输入CRC/有效字节/数量对照旧记录；诊断固件不是普通FPS资格。

选择门：若Key或Copy有显著B尾等待，再设计两笔在途写，必须连同行调度、写引擎与B-owner仲裁队列修改；若主要是R供应或准入空隙，转读预取。若两者都不足，先离线统计新场景细粒度背景覆盖和连续恢复区间，评估硬件自主恢复，不直接重开已失败的软件damage/条带路径。任何新优化继续同像素、失败排空与同场景A/B/A；没有净收益回旧路径。

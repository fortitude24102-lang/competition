# GPU HUD 字形图集与局部更新

用户批准顺序：字形图集 → GPU 局部更新 → 根据实测决定是否增加专用 DMA。

- CPU 比较路径保持现有 `hud_update_cache` / `perf_render_cpu`，不优化、不人为降速。
- Sapphire 负责指标文字格式化、字符差异判定、命令生成；PC 只提供现有资源。
- 保留 R7、960×540 RGB565、960×72 黑底 HUD、双缓冲、100 MHz GPU、当前位流与 Sprite Cache。
- 保留现有字体、颜色、位置，最终 HUD 像素与完整软件重建逐字节一致。
- 从现有 5×7 字体在启动时一次性生成两色 RGB565 字形图集；14×18 单元包括黑底和间距。
- 图集从 `0x02c40000` 开始，39 字形（A–Z、0–9、减号、点、空格），两色共 39,312 字节；不占 Sprite Cache。
- GPU 更新仅提交变化字符的 Copy；首次/失效时先 Fill 整个 HUD。文字变短必须复制空白单元擦除。
- GPU 完成后才提交缓存文本；失败标为失效，后续必须完整恢复。CPU/GPU 共用实际 HUD 缓存及其文本元数据，避免模式切换陈旧。
- 初始版本复用现有 GPU 命令队列与 Copy，不新增 RTL、外部依赖、操作码或专用 DMA。
- 不改 Flash / release/v2，不自动推送；板测只用 JTAG 候选固件。
- 同时测重建/命令等待、HUD Copy、完整帧及 P5；不得把工作量减少当成 FPS 实测。

参考：Fontstash 的字形图集思路、LVGL 的脏区域更新、Endeavour2 的批量 DMA；本阶段不复制第三方代码。

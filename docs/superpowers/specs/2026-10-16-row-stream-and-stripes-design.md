# GPU短行流水与片上条带合成

用户已要求依次实现方向2、3，并沿用本对话直接执行、不逐步审批的约定。基础提交53bcd61；不推送远端、不写Flash、不改CPU基础绘图或游戏负载。

## 顺序与兼容

先完成短行预取并检验，再接条带合成。两者均为显式生成候选，旧GPU生成参数默认不变；不将模块仿真通过等同于整机FPS收益。发现无收益保留可回退实现/证据，不强行作为发布默认。

## 方向2：缓存精灵连续预取

已有4KiB图集Cache与Key字掩码路径保持。新增CachedKeyStream，针对缓存命中、非重叠、源地址4B对齐、源行紧密排列、偶数宽≤16、高≤16的Key命令，一次请求整张精灵，通过16字FIFO预取后续行。目标地址可为半字相位，复用Rgb565WordAligner逐行生成首尾lane和Key WSTRB；DDR仍按真实stride分行写，不伪造跨行连续Burst。

只有整行数据已缓冲才承诺该行AW，故错误后仍能排空全部承诺W/B。缓存读与行写重叠；首个错误锁存，停止发起新行并排空剩余缓存读/已发写，最后仅完成一次。其他命令在任何issue前选择旧路径，绝不在部分执行后回退重放。暂不扩大仲裁器在途数量：收益先来自重用现有读写后端的预取解耦，后续若B等待占主导再改仲裁。

## 方向3：复用原像素引擎的片上条带

不重写Alpha/Key算术。增加15,360B（960×8×RGB565）AXI片上scratchpad及专用别名窗口0x02e00000..0x02e03c00。接在Render到现有DDR仲裁器之间，仅截获此窗口；其他Render、命令列表、Scanout和网口资源流量仍走原通路。初版单条带缓冲，先证明像素/事务/资源收益，再考虑双缓冲；不预先多用30KiB RAM。

每个条带依次：背景DDR Copy到scratchpad；按原提交顺序执行相交Alpha/Key；scratchpad Copy到真正back framebuffer。最后一个条带退休后才做原HUD和PRESENT。Sapphire仍生成原场景，再按Y范围建立条带命令索引/裁剪；不按纹理或地址重排覆盖顺序。跨条带的源offset、目标局部Y、部分末条带均精确裁剪。

CPU scratch布局：原场景0x02d40000..0x02d48000（2048描述符）；分桶输出0x02d50000..0x02d70000（8192描述符）；运行规划元数据另用小结构。每条带取对应范围复制到已有bankA/B再用原严格render_span，初版不扩大FrameList硬件可访问范围。缺少scratchpad能力位（STATUS bit16）时候选软件拒绝启用，不把别名写到真实DDR冒充成功。

AXI scratchpad分别保持读写owner到RLAST/B，合法local burst遵循32位INCR、长度/窗口边界、WSTRB、稳定背压。非法local burst回SLVERR且排空已承诺传输；外部通路完整透传。帧缓冲/显示仍在DDR，双缓冲不变。

## 验收

- 单元：缓存整张预取、后行在前行B停顿时提前到达；错位透明像素正确；错误/背压无丢失/重放。现有Key/Alpha/Copy/Cache回归不变。
- 条带：AXI local/DDR切换、读写独立、首尾/4KiB/别名末界/错误；C分桶对照原列表逐像素（有重叠Alpha和Key、半字X、跨8行和最后4行），无新游戏状态变化。
- 整机：候选RTL、原固件/条带固件分别检查；比较同场景事务数量、总帧时间、下溢、错误。资源/时序不合格不上板。仅JTAG候选，必要时恢复原BIT与正常MENU。
- 保留3600严格复核及资格后继续观察，不剔除慢帧，不降低Alpha比例/大小/元素数量。旧43/44.9退化与1015资格后迟到仍不能未经证据归因于任何新模块。

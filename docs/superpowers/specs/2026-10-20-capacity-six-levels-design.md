# 四块列表容量与六档游戏

用户要求扩展软件容量，并在原四档后增加786和1024。精确档位64/128/256/512/786/1024；不是768。不改CPU基础栅格算法、官方核、100MHz、资源服务器职责和Key/Alpha负载。继续本对话直接执行，不中途重复审批；只本地候选、JTAG/RAM，未获新指令不推送/Flash/release。

当前1819活动+228Alpha+1背景=2048项，DDR列表0x02d20000..0x02d28000，紧跟PC状态。硬件每批1024项片上预取。选择扩展DDR arena为4×1024项、0x02d20000..0x02d30000，PC状态搬至0x02d30000，状态末端仍不超0x02d40000；最大活动数3640+455Alpha+1背景=4096。每批仍1024，RAM不扩大。比扩大整批片上RAM省资源，比软件反复拷贝/流式重建列表少CPU额外工作。

新增默认关闭enableExtendedListArena / --extended-list-arena，要求frame-lists。FrameListReader/Batch只扩大白名单，不放宽16KiB分块、对齐、计数、错误与退休约束；Top STATUS bit20声明新能力。C gpu_frame_list.arena_items=2048或4096，初始依硬件能力选；所有span在任何START前完整校验。老BIT自动保留1819上限，不因C上限提高而访问第三块；旧BIN可继续在新BIT用前两块。pc_init最大由实际arena容量计算，源码协议最高3640。

正常游戏容量编译为BULLET_OBJECT_CAPACITY=1024（512旧构建仍可用），仅扩展存储不优化CPU渲染。多于一块的普通游戏列表从arena A开始，framebuffer A/B仍正常切换；退休前整个实际列表不可修改。运行时/回放/场景结构均在原私有DDR区域，静态断言和实际链接检查不越界，4KiB栈不缩。

协议保持32/128字节与version1，新增遥测status bit14表示六档支持，允许mask0x007f7fff；bit15仍保留。C/网关均验证level1..6，运行时依实际对象容量拒绝不可用档。新网页只在六档能力位有效且控制权/ACK/新鲜状态允许时启用5/6；旧固件仍可使用1..4。性能包最高3640，旧1819包仍合法。无伪造旧固件能力。

HDMI菜单2列3行，卡片x96/496，y144/232/320，高80宽368，文字y+14/+46；性能入口仍y412，高48，网络提示y480；顶部72像素性能/图片不覆盖。512旧构建保留4张原布局，六档配置cache键含档位数避免旧菜单缓存。网页增加5/6按钮、当前档位与选择映射；键盘、死亡回菜单、一键重选、CPU比较途中暂不可重选限制不变。

验证先RED后实现：旧/新arena发现、4096分4批、tag回绕/第三批失败不重放/整体越界零START、PC最大3640及DDR边界/完整生成/保护哨兵；六档运行时/回放/死亡/网络ACK、旧4档能力隔离、网页真实按钮/网关验证、HDMI输出命令几何/实际字形。仅对受影响RTL一次定向回归；新BIT全部最终时序正后才加载。实板检查第三/四块及普通6档、性能挑战；未达60的档据实报告，容量不是性能资格。

# 128位专用Copy DMA与32位像素通路：最终架构升级规格

日期：2026-10-22。设计基线：9c3b93c（Alpha跨行预取候选）。执行状态：用户随后明确“可以执行了”，已完成候选实现、回归、物理检查和A/B/A板测；背景Copy加快但正常游戏退化，按本文准入规则保持默认关闭并回到旧主线。[最终结果](../../efinix_2d_gpu/evidence/wide_copy_dma_20261022/README.md)。以下保留批准时的设计边界与目标，不把它们当性能承诺。

## 1. 目标与不可改变的边界

目标是在相同画面、Sprite数量、Alpha/Color Key工作量下，减少大背景Copy耗时，为普通游戏最坏帧及全活动挑战留出更多时间。PC仍仅提供资源、输入转发和遥测；Sapphire负责游戏、资源管理和GPU命令。CPU基础绘图算法/编译配置不优化。

首期只做原Copy命令的大块、连续、对齐快路径，不改全部像素模块的总线宽度。官方Sapphire生成源码、DDR PHY/训练、100MHz、DDR地址布局、HDMI分辨率与双缓冲、以太网协议和游戏逻辑均保持。共享内存仲裁可能影响CPU实测等待时间，但不能把该变化宣传为CPU算法优化。Alpha、Key、小块Copy与通用回退保留原路径；缩放、灰度及其独立演示在资源不足时可按第5节裁剪，用户已明确授权此条件性取舍。

原规格阶段仅提交书面设计；后续明确执行授权对应的实施计划与结果见文末。未授权推送main、写Flash或替换release的边界不变，候选上板仍须先过本文门槛。

## 2. 已有证据与选择依据

- 同BIN固定1040诊断：背景约5.55ms、Alpha约1.89ms、Key约1.64ms，完整原序渲染约8.88ms；是串行诊断，不是普通游戏帧。
- 普通1024候选各3600帧测得平均work13.408ms、最大19.226ms，仍有6帧超预算/迟到，不能称稳定60。
- Copy FIFO16字扩256字没有可信整机收益；8行片上条带合成在1024活动Sprite隔离测试中约8.036→15.893ms，不能重做相同缓存思路就假定提速。
- 活跃板级工程加载的官方文件是`board/efinix_ti60/vendor/sapphire_ddr3/par/ddr_demo_ti60/ip/soc/soc.v`：DDR出口128位，GPU用户入口32位；该文件包含的实际DDR ID接口为8位。目录内另一个`EfxSapphireSoc.v`不是本次宽度/ID决策的依据。
- `board/efinix_ti60/vendor/sapphire_ddr3/rtl/ddr3_controller/ddr3_parameter.vh`声明128位DDR AXI数据宽度；`efinix_sapphire_adapter.v`当前将SoC DDR出口直接接DDR控制器，并将控制器ID宽度显式设为适配器的8位。新接入保留这些实际宽度，不偷用假定空闲ID。

历史依据：[Alpha实测](../../efinix_2d_gpu/evidence/alpha_row_prefetch_20261021/README.md)、[Copy缓冲负结果](../../efinix_2d_gpu/gpu_memory_overlap_20261016.md)、[条带负结果](../../efinix_2d_gpu/row_stream_and_stripes_20261016.md)。

选择：增加真正使用128位数据拍的专用Copy后端，经受控仲裁接入现有DDR AXI入口；旧SoC出口作为另一主设备。不是再把32位数据包装成128位，也不是绕开显示保护直接抢DDR。首期不重做Tile、不扩纹理Cache、不超频、不增加跨Sprite乱序。

## 3. 组件职责与接口合同

### 3.1 Copy分流与GPU顺序控制

位置：现有Render/Dense命令验证及发射边界。新增尾部构建选项`enableWideCopyDma:Boolean=false`与生成选项`--wide-copy-dma`；关闭时不生成宽口硬件，板级保持原直连接线，不引入空闲附加延迟。开启时不要求新软件驱动或新opcode。

RTL生成与板级接线必须由同一构建参数启用，构建检查顶层宽口是否存在与适配器接线是否一致；不允许“GPU已启用、宽口被tie-off”或相反的半启用组合生成可下载候选。

既有CommandValidator先验证整条命令；快路径选择不能代替边界校验。仅满足全部条件的命令进入宽口：

1. Copy，宽高非0，RGB565，源/目的均位于现有Copy允许的DDR范围，禁止外设/IO地址。
2. 源地址、目的地址均16字节对齐；源与目的stride均等于width×2，整个矩形连续；总字节数为16的整数倍。
3. 使用扩展位宽计算总字节数与末地址，无溢出；源/目的完整区间不重叠；总长度至少4096字节。

当前960×468背景为898560字节，行宽1920字节，符合上述数据形状。运行时具体地址仍需验证；不是看见Copy就强制走DMA。合法但不符合快路径的命令在任何新总线事务发出前走原实现。

复用原GpuCommand/GpuCompletion字段及错误码。GPU只允许一条Copy命令占有此后端；外部只见一次完成。背景Copy最后所需B响应及读事务全部退休后，后续依赖像素命令才可开始。PRESENT、列表批次完成、LAST_DONE/tag/epoch不得提前；错误后禁止用旧路径重放已部分执行的Copy。

### 3.2 WideCopyDma：128位搬运后端

输入为验证后源地址、目的地址、总字节数和原tag；输出为原tag/错误的完成握手。内部地址保持32位，连接DDR地址端前做合法范围检查而非静默截断。

- 单拍16字节、INCR、SIZE=4；每段最多64拍（1024字节），分别遵守源/目的4KiB边界。两端16字节对齐，分段长度仍为16的整数倍。
- 数据缓冲固定两个1KiB bank，首期2KiB有效数据容量，不堆任意深FIFO；物理RAM块数以综合结果为准。metadata不与像素内容重复保存。
- 读、写发射与响应退休分离，各最多两笔在途。读发射前预留完整突发容量；写AW发射前，整个对应突发的数据必须已就绪，防止显示保护阻断后形成读写互等。
- 本后端使用一个固定本地ID；同ID顺序处理。每个已接受AR保存拍数/段归属，每个已接受AW保存W与B归属；B不能代替尚未完成的W，FIFO bank复用不能破坏在途响应metadata。
- 全1字节写掩码；首期无未对齐DRE、无边缘半字处理、无压缩/颜色计算。需要这些情况时原像素路径处理。
- RRESP/BRESP错误、错误ID或RLAST不匹配锁存命令错误；已知错误后不发新的段，但已接受/已呈现的事务必须完成协议排空。未写出的错误读数据丢弃；已承诺AW的W从完整bank供应至末拍。所有计数/缓冲/响应归属排空后仅完成一次，后继命令不继承旧数据或错误。
- 假定DDR为有限延迟、按所承诺拍数返回的AXI从设备；缺失响应/任意非法拍数导致的不可排空不允许靠清owner假装完成，软件超时后需共同硬件复位恢复。

### 3.3 WideDdrMux：旧SoC与新DMA的两主一从仲裁

集成位置为`board/efinix_ti60/rtl/efinix_sapphire_adapter.v`原SoC DDR出口与`u_ddr3_top`之间。保持128位数据、现有8位ID及DDR地址端宽度；不修改官方`soc.v`或把全部GPU类型改成128位。只构建固定两主一从，不引入通用N×M交叉开关。

首期采用每方向独立的owner，而不是假定未占用的ID命名空间：

- AR/R方向和AW/W/B方向分别记owner及未退休计数。一个方向存在任何未退休事务时，不切换其owner；R/B仅送给该owner，旧SoC的ID原样往返。
- 旧SoC可使用其原有不同ID；首期每方向最多跟踪16个未退休事务，满时只对尚未接受的地址反压，不降低原四笔写支持。DMA每方向最多两笔，不能凭ID位宽推断已排空。
- 写数据必须跟随已接受AW的顺序和owner，不能因新AR或新仲裁选择切走W。W比AW先到时可以反压，但不得错误配给另一主设备。
- owner有待切换请求时，停止该owner进一步新地址准入，排空已承诺事务后切换；在下游反压期间已呈现VALID的地址保持稳定，不能撤回。读写方向可由不同owner占有。
- 只有另一方满足准入条件时才启动上述停发切换。显示紧急而DMA尚未呈现地址时，取消尚未承诺的DMA切换，继续允许旧SoC补充显示数据；不得出现“等DMA切入而停住旧SoC、DMA又被紧急保护禁止”的互等。
- 切换还要求不存在已呈现但未握手的地址、未结束W突发；计数归零与新AR/AW接受同拍时必须先合并增减事件再判断，不能用旧的零计数误切owner。每方向计数不溢出/下溢，DMA读bank信用和写响应信用分开管理。
- 无紧急显示需求时，两方有请求即公平轮换；DMA每次owner连续准入至多两段后让出，CPU/网口路径不能被长Copy无限饥饿。不能等整幅背景Copy结束才让显示取数。
- DMA空闲时旧路径必须正常推进；编译开关关闭时完全保留原路径。开启时增加的仲裁反压需计入实测，不承诺旧路径逐拍延迟完全不变。

这样可以在不扩展官方DDR ID位宽、不依赖其内部ID分配假设的前提下安全分流。代价是两个主设备的同方向响应不能任意交错；首期接受这个限制，不为少量并发收益增加跨ID重排系统。

### 3.4 HDMI紧急保护与复位

复用当前GPU时钟域的Scanout FIFO水位/紧急状态，将其显式送达宽口仲裁。低水位/紧急时停止DMA新AR/AW准入，优先让旧路径补充显示数据；已呈现地址和已承诺R/W/B继续排空。两笔1KiB上限只限制DMA阻塞量，不能当作DDR延迟的硬性时间保证。

显示保护验收包含最差两笔在途、DDR刷新/反压、同时资源DMA和CPU访存；需要计算FIFO余量并实测安全性。不得降低现有低水位保护或隐藏下溢来取得带宽。

新后端和仲裁均用现有user_clk，首期不新增时钟域。fabric所有权、计数器和DMA承诺数据的生命周期必须覆盖其DDR事务：共同DDR复位可共同清状态；单独GPU复位不能清掉仍需送还旧SoC的响应。

GPU复位但DDR未复位时，后端停止新事务/新命令，排空所有已呈现或接受的DMA事务，再丢弃旧完成、清GPU私态；新GPU命令直到此时才可接受。数据bank和排空metadata不能随局部GPU复位提前清除。不得把旧完成投递给重启后的新命令；旧SoC通路及其在途事务不随此局部复位丢弃。若此合同无法可靠实现，不得集成局部复位路径或上板。

## 4. 性能计数与兼容性

原APB地址、opcode、tag、错误处理和正常固件BIN保持。将后端活动、像素数和字节事件并入现有统计：宽口R每拍16B，W按16位WSTRB有效字节计数；原窄口仍4B/拍。活动/停顿周期按时间并集计，不把两通路重叠时间相加。不得让现有busy、read/write bytes因绕开32位端口而漏计。

内部事件必须能表达宽拍：全有效W每拍8个RGB565像素，像素增量至少4位；字节增量至少5位，并正确容纳同拍合法事件相加。原计数器的2位像素事件、4位WSTRB和固定read+4不能直接接宽拍；允许增加宽事件/内部汇合，但旧寄存器地址、单位和关闭选项时的结果保持不变。只在实际握手时累计，不能在请求等待中重复计数。

原AXI诊断计数继续明确标为旧32位通路，不把两种拍数混合。宽口事件在验证平台/测量出口单独保留；没有测量依据的DDR物理利用率、CPU利用率不新增为“真实”指标。网页首期不改版，原已有仪表的含义不能静默变化。

配置回退为完整重建/重载旧BIT，或关闭新构建选项；不支持活动命令途中切换后端。仅JTAG/RAM验证，沿用全BIT重载后加载固件的流程，避免此前热重载显示相位问题。不能在已经执行了一部分新Copy后回退重放。

## 5. 资源、时序和依赖预算

基线XLR52866/60800、RAM179/256、DSP37/160；当前core setup/hold +0.264/+0.003ns，保持裕量薄。新后端无乘法/DSP需求；新逻辑净增目标≤1500 XLR，全板必须仍<54720 XLR；RAM必须<256块，数据缓存预算首期仅2KiB，不能把RAM富余当理由随意扩容。

独立后端综合先验证规模，随后完整工程综合/布局布线，以最终报告为准。最终16项setup/hold均必须严格为正，网口现有mapped/routed CDC覆盖和8ns约束继续通过。不能仅看局部模块频率或忽略新增128位扇出路径。正裕量仍不等于温漂长稳认证。

### 5.1 资源不足时的功能裁剪（2026-10-22用户追加授权）

优先保留比赛核心和GPU性能，不为附加演示阻断宽口后端。若完整候选超过资源预算，或可选模块导致布局/时序难以通过，允许关闭缩放、灰度及对应按键独立演示；不是现在无条件移除。先查层级资源/关键路径，裁剪后再综合，不假定删功能必然解决时序。

现有缩放和灰度同属`TransformBlitEngine`，已有`--transform-blit`/`enableTransformBlit`生成开关；优先在性能候选中不实例化整个可选Transform通路及其专用寄存器/能力位，避免再造一套裁剪框架。灰度自身是加移位计算，并不单独占4个DSP。基线层级报告的整个transform约1299 XLR、4 DSP、0 RAM，仅作裁剪潜力估算；全板净释放量必须重新综合，不能直接从总数减去后宣称实测。

裁剪时同步禁用相应固件入口/展示、正确清除能力位；旧正常六档游戏必须继续工作，不支持的Transform请求明确拒绝且不能挂起或静默绘制错误。Alpha/Color Key的像素通路、DSP、纹理缓存、性能计数与错误处理不得误删。源码、测试和旧已验证BIT保留以便恢复；删除文件本身并不节省FPGA资源，关键是候选网表不再生成该模块。本授权不要求删除历史文档或证据包。

以太网、官方RISC-V、基础Copy/Fill、硬件Alpha和Color Key、DDR/HDMI、双缓冲、游戏菜单/输入与性能统计属于必须保留项。裁剪允许项后仍不能通过资源/时序门槛，则停止新架构集成、保留旧候选，不继续牺牲这些核心功能。

参考[verilog-axi axi_cdma](https://github.com/alexforencich/verilog-axi/blob/master/rtl/axi_cdma.v)的描述符、读写解耦、4KiB拆分与退休思路；首期复用本工程接口/验证设施并实现限定功能，不整体搬入通用库，不新增运行依赖。未来如直接引入第三方RTL，须另行固定版本、核对许可/依赖，并遵守一个生成`.v/.sv`文件一个模块。不能把同名DMA模块的存在当作本工程性能证据。

## 6. 验证与收益准入

实现计划必须测试先行，覆盖实际数据和事务，而非只检查busy/寄存器：

1. 新后端逐字节对照：4KiB起点/跨边界、1KiB分段末尾、多个bank、随机AR/R/AW/W/B反压、延迟/错误响应、每个错误位置、数据稳定、信用耗尽及后继命令恢复。验证真正发出128位SIZE4事务，不能仅在外层把32位数据复制到宽总线。
2. 混合仲裁：两主相同ID、旧SoC多个不同ID、读写不同owner、多笔旧响应未退休、新旧同拍握手、W先于AW、显示紧急插入、满计数、局部GPU复位及共同复位。断言无串响应、无丢失/重复、无VALID撤回，旧四笔Key路径不受无故限缩。
3. 整链路：同一Copy命令在开/关路径输出及哨兵一致；不满足快路径回旧路径；Copy→Alpha/Key→HUD→PRESENT顺序、最后B之后完成、错误不重放、计数真实一致。原颜色键透明行为、Alpha像素及字节边界不改变。
4. 资源/时序/CDC过门后才能加载候选；用相同BIN和相同资源，先旧→新→旧大Copy/固定阶段，再普通1024至少3600帧及原全活动挑战规则。未改变的已通过长套件不为提交重复运行；接口受影响的回归必须覆盖。

若启用上述功能裁剪，先生成同样关闭缩放/灰度、但宽口DMA关闭的控制BIT，再与相同功能集的宽口候选做同BIN A/B/A；完整旧BIT只作历史兼容参考。功能裁剪、物理布局变化与DMA本身的收益分开记录，不把两项一起改变后的差异全算成DMA提速。增加裁剪能力位/非法Transform拒绝/正常游戏兼容检查，不重跑已移除独立演示的上板交互来冒称其仍受支持。

项目目标是背景Copy相对本轮同场景基线至少减少30%（约5.55ms→不高于3.89ms），是待验证的目标。达到该目标仍不足以宣称整帧收益：正常游戏work/尾延迟必须分别实测，零新增下溢/错误；普通1024与全活动挑战继续分别判定。若仅局部改善、普通帧无可重复收益，记录结果并保持旧路径为主线，不强行启用。

不承诺128位带来四倍游戏FPS，不预告3000 Sprite@60。任何新BIT都重新取得自己的3600帧、零超预算/迟到/下溢/错误及资格后保持证据，不能套用旧BIT的2194记录。失败窗口不删除，短窗不计极限，搜索策略/负载/门槛不与本次硬件A/B/A同时修改。

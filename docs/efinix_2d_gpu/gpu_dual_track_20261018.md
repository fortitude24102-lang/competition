# GPU性能与功能双线设计（2026-10-18）

基线b7b34cd。用户批准两条线并要求立即执行；沿用本对话连续执行、无需中间重复审批的授权。先交付下列首轮，不把后续研究项说成已完成。

## 共同约束

- 官方Sapphire、100MHz、DDR、HDMI、以太网与CPU基础渲染保持不变。
- 原命令0..6、旧BIT/固件、实例/列表和原资格规则保持兼容；新硬件显式开关、默认关闭。
- 手工.v文件一个模块；Chisel生成使用split-verilog。仅JTAG/RAM，禁止Flash、禁止GUI烧录；检测不到就绪板卡时只做离线工作。
- 同像素、原序Alpha/Key、随机背压、错误排空和完成顺序是性能验收前提。减少W拍不等于提高整机FPS。

## 性能线首轮：缓存Key透明行裁剪

仅扩展现有CachedKeyStream：在承诺写请求之前持有完整目的行，比较Key并得到首/末非零WSTRB字。空行不发AW；非空行只发该连续字范围，中间孔洞保留零WSTRB。不把每个孔洞分裂为短事务。源完整预取、≤16×16、紧密行、缓存命中、无源目的重叠等原资格不放宽。

构造参数`enableKeyRowTrim: Boolean = false`贯穿顶层/Render/Dense至CachedKeyStream，必须依赖KeyPrefetch。默认生成与release不变。保留`CachedKeyStream`旧路径用于A/B。统计仍计入所有被处理的透明像素，不能只统计实际写出的像素；现有有效字节计数不冒充实际总线占用。

首轮验收：同素材/Key/掩码/结果；全透明行AW为0，首尾裁剪降低W拍；半字相位、奇数目的跨度、暂停稳定、错误时完成已承诺写并排空未用输入。测试直接记录AW/W/B，而不是用有效字节推算W拍。

## 功能线首轮：可选硬件StretchBlit与镜像

新增opcode7 `Transform`，只由显式`enableTransformBlit=false`开关开启；STATUS bit17声明能力。旧BIT不支持时C帮助函数拒绝提交，旧命令无需新能力。源与目的均RGB565；第一版不用Alpha、纹理Cache或插值滤波，不接普通/挑战循环。

用户随后明确要求板上两键按住持续缩放，按下时长决定程度。为避免只有0.5/1/2三个档位，首轮升级为任意正源/输出尺寸的最近邻缩放。原寄存器及原命令字段语义保持；内部Chisel GpuCommand尾部增加16位srcWidthPixels/srcHeightPixels。C接口保留`src_width_pixels/src_height_pixels`名称，但不增加原32字节gpu_command：Transform不用的`color`、输入元数据`tag`空间分别与源宽、源高使用union复用，原字段偏移不变。Transform不能同时赋旧color/tag与源尺寸；驱动仍独立分配实际提交tag，ColorKey寄存器的无用纯色低半字保持0。原先C尾部扩展为36字节会让HUD/场景数组增加空间、完整游戏固件片上RAM超出1648字节，因此不能采用；不缩栈、不降容量。新增APB `TransformSourceSize=0x00a8`，低16位源宽、高16位源高，仅新命令使用；旧16B实例描述符不变，其新内部源尺寸字段默认0。

width/height表示输出尺寸，flags只允许bit0水平翻转、bit1垂直翻转、bit4开启Key（Mask=19），其他位错误TransformConfig=10。四个尺寸均须1..65535；源/目的地址与stride为偶数，按各自完整矩形64位范围检查并禁止重叠。精确映射sx=floor(x*sourceWidth/outputWidth)，sy同理，再按完整源尺寸镜像。硬件用加减比较的残差DDA，不推入大型组合除法器；极端缩小可能较慢，第一版不保证此路径的游戏60FPS。软件不预展开像素，不把缩放运算放到PC。

独立`TransformBlitEngine`复用现有AXI读/写引擎，逐像素有序执行，正确性和有限资源优先；允许较慢，不宣称它提高原Sprite基准。响应错误即停止后续像素，排空既有事务，只退休一次；透明像素不写。顶层共享原DDR仲裁，完成/PRESENT顺序不改变。

首轮验收：非对称素材的整数和非整数放大/缩小/双向镜像、Key、stride和半字写掩码；非法flags/零尺寸/越界/重叠在任何AXI前拒绝；R/B异常、背压稳定、命令连续性；原命令0..6与默认关闭回归。C驱动提供`gpu_transform_blit_async(d,src,dst,src_stride,dst_stride,src_w,src_h,out_w,out_h,flags,key,tag)`，必须先能力检查；CPU参考栅格算法不改。

### 板上两键缩放交互

先在独立GPU功能演示接入，普通游戏和性能挑战保持原尺寸、原工作量。KEY1按住缩小、KEY2按住放大；同时按下不变；松开保持。默认1.0x，范围0.25..4.0x，按住每秒变化0.5x，20ms消抖并使用真实毫秒时间，控制器本身无等待。单次未观察轮询间隔最多累计250ms，防止阻塞后跳变；演示在绘制之间轮询，屏幕按整数像素4..64变化，不是连续亚像素插值。官方复位键KEY0不复用。官方8月13日指南表及配套按键Demo约束一致为KEY1=P14/GPIOR22、KEY2=N14/GPIOR21，低电平按下、3.3V上拉；旧3月原理图页的按键/LED标签相反，不能据此冒称物理验证。新增按键输入专用端口，保留原LED27/24管脚与输出/OE，经过2FF同步后送软核GPIO低2位，不能驱动按键触点。Sapphire只管理比例/目标矩形，GPU完成像素缩放。

## 后续顺序，不混入首轮

性能：先记录实际W拍/空拍/响应等待，再做Alpha连续流水；双在途写仅在B等待确有占比时推进。此前Copy256和条带负结果保留，不强行启用。

功能：按需真像素截图→低帧率缩略预览→在实测原始/RLE/QOI后选压缩；逐像素Alpha随后。现有网口32/128字节邮箱不是图像DMA，截图需独立分块/CRC/帧所有权/发送优先级合同，不直接挤入控制包。PC仅解码展示，不参与游戏或绘图。首轮不接入截图、JPEG、视频编码、3D/OpenGL。

## 证据与停止条件

定向先RED再GREEN，最终GPU套件只运行一次；软件全回归保留已知SoC异常边界。仅最终生成候选才做资源/时序；任何收益只在同BIT/BIN/场景A/B/A与完整资格后宣称。无明确净收益保持旧路径；时序/资源失败不替换板上稳定版本。记录未完成的综合、板测及后续项目，不用局部仿真冒充两线全部完成。

# V1 缺口硬件侧验收记录

日期：2026-09-21

范围：V2 计划第 2 天负责人硬件合同验证

结论：负责人自生成向量已通过；本记录不是板上 FPS 结论。

## 验证方法

`Efinix2dGpuTopSpec` 按 `v2_interface_contract.md` 的固定档位生成 16、32、64、96、128 条 Sprite 等价命令。每条命令使用 1×1 RGB565 FILL，因而每条成功命令应精确贡献 1 个完成像素。命令通过真实 APB 影子寄存器和 SUBMIT 路径进入 16 项队列，再经过真实 RenderEngine、PixelPipe、DDR QoS 和 AXI 写通路完成。

每档开始前清零运行计数器；命令按最多 16 条一组提交，在 AXI 反压期间先形成队列，再释放 AXI 并等待 busy 清除。每组检查 LAST_DONE 和 ERROR，每档结束后原子 SNAPSHOT 并读取 64 位 PERF_PIXELS。

## 固定结果

| Sprite 档位 | 分组数 | 首 tag | 末 tag | PERF_PIXELS | ERROR |
|---:|---:|---:|---:|---:|---:|
| 16 | 1 | `0x1000` | `0x100F` | 16 | 0 |
| 32 | 2 | `0x1100` | `0x111F` | 32 | 0 |
| 64 | 4 | `0x1200` | `0x123F` | 64 | 0 |
| 96 | 6 | `0x1300` | `0x135F` | 96 | 0 |
| 128 | 8 | `0x1400` | `0x147F` | 128 | 0 |

结果证明：所有档位均无 SUBMIT 错误，队列最终排空，末 tag 与提交序列一致，完成像素数与命令数严格相等，硬件错误码为 0。独立的 `CommandQueue` 测试继续负责逐项顺序和满 16 项同时入队/出队边界。

## 与 B 组文件的边界

以上向量由负责人按冻结合同独立生成，不依赖 B 当日实现。B 提交 `tb/vectors/stress_vectors.bin` 后，只需按合同检查文件头、body CRC、tier 描述符和命令记录，并把解析后的各档命令喂给同一验收路径；不得为了适配 B 文件而改动已经冻结的二进制格式。

仿真只证明硬件命令不丢失、tag 顺序合同成立、计数不丢失。稳定 60 FPS 上限必须由 B 在同一候选位流上按每档 300 帧、固定种子、p5 FPS≥60、underflow=0、hardware_error=0 的规则实测，不能用本记录替代。

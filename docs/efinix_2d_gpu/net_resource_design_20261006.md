# 保留以太网功能的资源压缩设计

用户已批准按负责人判断在本对话执行；不额外增加功能或更换 MAC。

## 边界与目标

保留千兆网口、资源 GET/DATA/CRC/会话校验、输入、遥测、超时与恢复；PC 仅资源服务器/输入与遥测中继，官方 Sapphire 管游戏与资源调度。CPU 绘图、GPU 基线、游戏、美术、厂商源码和 release 不变。每个新增 .v 仅一个模块。上一轮默认关闭的实例前端原型保持独立，不作为本轮板测硬件。

1. asset_udp_rx 的 32 B 头字段保留寄存器，1024 B 负载使用同步读 RAM。整包验证通过后才给 DMA 元数据和负载。读数据在背压期间保持，每个已接受字节后预取下一个，保持原 valid/ready 接口与顺序，无部分坏包泄漏。
2. 仅资源请求 384×4 和管理 TX 1104×4 改为单笔在途跨域邮箱，现有 busy 限制直到发送完成，因此不会降低原可接受的并发。输入 RX 四项深度、元数据 FIFO、负载 FIFO 和完成 FIFO 保留。邮箱双方由 wr_reset|rd_reset 共同异步复位，各自同步释放；传递捕获后的数据快照，收端锁存后才确认，背压不改变数据。邮箱异步 req/ack/data 路径明确约束 <=8ns，不添加全局 false path。
3. 先以正式 GPU 生成物与同一固件做网络回归、完整 Efinity 编译和最终 STA；仅全部通过后 JTAG 临时加载。资源验收：解析器 <=2000 XLR 且 RAM>0；两个邮箱 RAM=0；总 XLR<90%。这些是门槛，不是已测结果。若映射失败定位原因，不隐瞒负时序、不降频蒙混。

## 复用依据

设计思路参考 LiteEth mac/sram.py 的数据/元数据分离、MIT verilog-axis axis_fifo.v 的同步 RAM/坏包提交方式、PULP common_cells cc_cdc_2phase.sv 的稳定快照/双向握手。此轮自有最小 Verilog 适配，不整库复制；厂商 RAM 属性以已有 Efinity FIFO 的 syn_ramstyle="block_ram" 模式为准。普通两相 CDC 不支持任意单边热复位，本工程继续使用已有双域共同复位，独立断言必须清空双方事务。

## 验证

解析器原有最大包/CRC/错误类型/截断/会话/背压/超时回归；增加非周期负载、逐字节停顿和复位后无旧负载。邮箱异步时钟、背压快照、二次事务、任一端复位清空、源数据变化不影响已提交包。真实 MAC 管理与资源混合回归、负责人 APB 胶合、资源报告与所有最终 setup/hold 行。上板资源实际加载、真实 HTTP/UDP 输入/遥测，恢复合格互动固件；不把资源节省当 FPS 提升。

## 后续取舍

输入/元数据浅 FIFO 的窄流打包及共享包池暂不做：先验证本轮净资源收益，保留输入排队和溢出规则。不搬整套协议到 CPU，不给网络新增 DDR DMA 与 GPU 争用。

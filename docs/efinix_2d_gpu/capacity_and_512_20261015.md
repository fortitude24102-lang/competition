# 普通512最坏帧与双bank容量扩展（2026-10-15）

## 结果边界

最终512 LIVE终止探针同一BIN关/开HUD直接更新，各30帧预热后完整统计3600帧，均60.1FPS且work_miss/late/under/errors为0。死亡等待、重开和重开后完整场景均统计，未筛除超时帧。可见499..504、Alpha66..67，不能称为512全活动Sprite挑战。没有复测CPU绘图成绩，CPU慢比较途中一键重选限制仍保留。

双bank容量为1819活动Sprite，每8个额外绘制12×12 Alpha光晕，场景命令1+1819+228=2048。全部Sprite都在屏内运动，Color Key开启；首个16×16，其余8×8。容量不是GPU物理上限或1819@60承诺。新挑战仍按原600帧搜索＋3600帧严格复核＋5秒继续观察判定，任何后续超预算可作废成绩。

最终普通菜单固件性能挑战复核和最终板卡状态见下方收尾记录；不把中间固件成绩套到最终BIN。

## 定位与改动

### 重开时重复生成和无效运算

原`bullet_reset_player`先调用`bullet_reset`生成全部对象，再设interactive/敌机HP、覆盖全部对象生成一次。第一遍最终状态完全不保留，现改为先确定最终模式、一次生成。round_tick0的敌机插值恰好位于固定中心，航点计算权重为0，直接使用中心；其他tick不变。真实函数入口计数RED→GREEN，旧两遍参考与新结果逐字节一致；冻结R7和互动回放/像素检查通过。

带细分计时的同组实验：

|阶段|HUD直接更新|帧数|work最大ms|最坏logic ms|work miss/late|
|---|---:|---:|---:|---:|---:|
|修改前|关|600|24.613|15.382|2/2|
|修改前|开|600|23.146|15.203|2/2|
|仅去掉被覆盖生成|开|600|18.397|10.705|2/2|

前三组最坏帧是hp0、death_wait1→hp3、round_tick0的重开；最终最坏帧已变为普通tick91（不是声称重开恰好耗2.481ms）。不同构建代码地址也变化，表格为端到端观察，不把所有差值等同于某个算子独立成本。

### 复用已存在的初始回放快照

600细分帧通过后，不带细分计时的3600帧仍有14次超预算。因此未以短测宣布合格，也未删掉重开帧。

`recording.initial`本来就保存规范初始游戏状态，且在录制/封存过程中不变。新增`reset_initial_valid`只在新初始化/新游戏后置位；更换epoch和GPU回放返回LIVE（其回放起点可能是游戏中途）时清除。仅LIVE自动重开可复用，不修改CPU/GPU回放路径。现有step输入/状态/每个对象的全部检查先执行，死亡倒计时正常结束、tick正常增加，再复制初始快照并保留该tick，最后照常处理预留子弹槽。显式R仍走原重开路径。没有新增10KB状态缓存。

真实运行时测试捕获旧路径再次调用512对象生成的行为（RED），现在不再重新生成（GREEN），同时与原`game_update`逐字节对照；输入R/比较、无效对象拒绝和中途epoch失效回退均检查。既有620逐帧状态对照、600tick CPU/GPU回放及黄金像素不变。

### 退化原因的事实与尚未证明部分

本轮明确的瓶颈是自动重开重复生成；现最终3600帧探针通过。不代表已证明上一轮43.0/44.9FPS旧BIN的每一部分慢在哪：旧BIN关掉HUD直接更新仍慢，而增加细分计时后的布局又不同。代码布局/单路缓存冲突有可能，但没有硬件计数或地址隔离对照，不能写成已确定根因。旧BIN和原始失败数据仍在上一轮证据包，不删除、不把旧失败改成成功。

尝试过GPU列表构建“屏内Sprite免裁剪快速路径”，21600帧字段等价/像素样本通过，但3600实板仍14次迟到、未见收益，已恢复原路径。该失败BIN身份/原始日志保留。

## 双bank实现和内存

普通游戏仍使用单bank函数。性能挑战独占连续双bank，**不随物理帧缓冲B而从bankB开头构建**：

|用途|DDR范围|所有权|
|---|---|---|
|描述符bankA|02d20000..02d24000|同一性能场景|
|描述符bankB|02d24000..02d28000|同一性能场景|
|性能状态|02d28000起，静态断言末尾≤02d40000|CPU挑战逻辑|

`pc_build(...,capacity,...)`在写任何描述符之前检查容量及所有Sprite。`gpu_frame_list_render_span`在任何START前验证完整范围，然后依bank界限调用原严格单bank执行：完整2048分1024/1024；提前Copy已执行、跳过第一条时2047分1023/1024。保留背景→所有Alpha→所有Key顺序，每段真实排空，再进行HUD/PRESENT。第二段错误、超时或错误Tag保留poison状态，不重放、不显示半帧。

1819初始化网格超过原19行后折回屏内，始终移动；旧909布局保持。C/Python网络报告上限一起更新，保留旧909数据兼容，网页不把某一编译配置的容量写死成当前成绩。

实际板卡2048/2047条执行读回像素均554483e0，透明Key不覆盖Alpha结果；Tag回绕2046/2045，目标两侧及02d28000状态哨兵不变。真实MMIO模型额外检查非法范围、零数量、溢出、第二段错误/超时且无重放。

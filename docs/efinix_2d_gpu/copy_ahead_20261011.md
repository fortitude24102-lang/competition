# 背景 Copy 与 GPU 命令构建重叠（2026-10-11）

## 结论

有净收益，保留为可启用的负责人候选：**512档30.0→42.6 FPS，帧工作均值19.513→15.917 ms，约减少18.4%**；更长600帧采样为42.7 FPS。但300帧仍有123帧工作超预算/呈现迟到，600帧仍240/243帧，**没有达到512稳定60，也没有完成30分钟耐久**。

256旧→新→旧均60.1 FPS，工作均值14.151→12.694→14.152 ms，约节约10.3%，300采样帧工作超预算、呈现迟到、新下溢和错误均0。这里只承诺本轮窗口，不保证长期稳态。

没有新加CDMA、Cache、乘法器或改变时钟：让已经存在的背景搬运先启动，软核在其执行期间生成相同Sprite指令。不少收益来自调度重叠而不是降低像素工作量。CPU基础绘图、菜单、游戏/回放校验语义、Key/Alpha及分辨率不改。

## 实现及公平边界

源码基点`8d84a17`。继续使用官方Sapphire与已合格GPU/SoC100 MHz位流，SHA256 `202d2b40ba1b919394a2cc920055a810e56c07fbd725fdb4185385124f894cf3`，960×540 RGB565经HDMI两倍显示。本轮仅JTAG固件，不写Flash、不更新release、不重新综合未修改的RTL。

`sw/efinix_gpu/src/v3_demo.c`的`V3_COPY_AHEAD`默认0；启用时：

1. LIVE/GPU帧在完成游戏更新、确定backbuffer后，用原驱动排入同一个960×468背景Copy，不等完成。背景/图集已在初始化完整同步，背景源此时不可变；不新增一次全Cache清理。
2. Sapphire继续原`game_build`及HUD区域裁剪，原后置同步保留。
3. 比较原流第一条Copy的实际地址、尺寸、步长、操作/flags；不匹配则停止，不发布半帧、不重放部分命令。匹配则从第二条依原顺序提交，不能重复背景。
4. 原有序GPU保证背景先于读改写Alpha；最后tag退休及HUD完成后才PRESENT。CPU模式与菜单仍走原路径，既有边界校验、tag、错误和超时处理保留。

源/目的各898560 B背景流量未减少。正常缓存资源101/102/103均CRC通过、重试0；启用原纹理Cache、Key及Alpha，seed7、零方向键，不删Sprite、不优化CPU绘制。

终止诊断在`0x02d10000`私有DDR控制字读一次0/1；位于runtime之后、不与资源重叠，正常候选不读取它。JTAG在加载后、resume前写入，**512旧/新/旧使用相同BIN**，只有调度开关不同，避免重新编译引起函数布局差异。原热函数地址/长度保持；V3入口增长。开关0运行接近上一轮原512均值19.60 ms，但这不是跨日期严格对照。

这是按真实时间更新的LIVE测试，不是固定逻辑帧回放：渲染速度变化会改变每帧追赶逻辑步数及被采样的tick。短组旧采到约658tick，新采到470tick，**不能声称同300个逻辑状态逐帧等价，或18.4%全部是背景硬件加速**。等价由独立真实构建器/驱动像素检查保障，实板数字是整条LIVE路径净收益。

`work`包含上一PRESENT后至本PRESENT前完整工作；`wall`还包含PRESENT等待。新`scene_us/render_us`从命令构建后计时，仅含尚未被隐藏的场景提交/执行及同步；**不能与旧scene字段直接比较为GPU算力提升，也不能与busy相加**。GPU busy包含搬运/等待，与软核构建重叠，仍不是纯像素计算耗时。CPU比较计时和绘图配置不变，本轮未重测CPU成绩。

下一项负责人方向：以命令构建、信用轮询/提交阻塞和GPU尾部为对象做语义一致的最小测量，寻找减少命令准备/访存的路径；同时单独评估维持回放完整性的渐进校验。先比较净帧成本，不因写次数减少或背景带宽变高就接入；不优先加大Sprite纹理Cache，原小图集已缓存。硬件升级须有定位证据、资源/时序预算和旧路径对照，不承诺新DMA必有收益。

## 验证、容量和菜单

- `test_copy_ahead.c`实际包含候选源码，链接原GPU驱动、真实游戏构建器/裁剪器及golden渲染器。600次游戏更新中取20帧完整960×540像素检查，涵盖本地/网络资源及A/B缓冲；比较实际MMIO命令字段、顺序、数量与最终像素。覆盖提前提交不等待、不重复Copy、单背景最终等待、不匹配/空流/地址错误、硬件错误和满队列超时。MMIO fixture在commit执行golden，**不是FPGA像素读回或硬件并行时序证明**；真实并行净收益另由板测给出。
- 实际行为RED（stub返回参数错误，断言失败）→GREEN；此前Shell参数/缺头文件的编译失败只是环境修正，不算RED。最终`test-v3-integration.ps1 -SoftwareOnly`通过17项C及23项UDP/HTTP检查。没有重复无改动的长RTL仿真，既有两项SoC固件测试异常不冒称修复。
- ELF静态text+data+bss+4096栈预算上限126976 B：终止候选126924 B，余52 B；正常候选126164 B，余812 B；默认旧正常125724 B，余1252 B。**不是运行时栈峰值保证**，沿用`-Wstack-usage=2048`单函数检查；诊断余量已极薄，不继续无预算堆探针。
- 正常候选真实四档START/MENU各一次，8次执行ACK及更新后的快照通过，资源零重试、新下溢/错误0；结束在MENU，控制权释放，服务保留。短场景首窗口受切换影响约58 FPS，不作为各档稳态成绩。
- 首次菜单验证失败保留原日志：测试脚本刚POST新请求即沿用100 ms轮询缓存，上一会话request1已完成被当作新START，板上仍MENU。网关实际将新请求置pending，不是Copy改变菜单。补实际`Game/Wait`函数离线回归，复现失败后，POST之后清空缓存并强制刷新；修复后四档实板通过，网关/游戏固件不因此改动。脚本新增可选COM端口，本轮COM9；5项离线防误加载检查通过。
- 正常候选额外补256档真实RIGHT/UP/EXPIRE三个阶段。原UART及阶段字符偏移经既有`control_evidence.py`检查通过，两个方向均有同阶段前进的tick/sequence及实际位移；停止心跳后零按键、age=-1，采样新下溢/错误0。控制脚本默认Python路径不存在，首次整体退出1，不能称该命令整套成功；采集与finally回MENU/释放已执行，改用本机现有Python单独校验同一份原始轨迹通过，没有重跑或重载板卡。原采集与独立校验均留证。
- 本轮没有重新目视验收、全四档方向/死亡矩阵、600tick实板CPU慢回放或30分钟耐久。既有CPU比较单帧超控制租约限制仍保留，不新增CPU轮询或改成绩。新的调度还没有作为正式release的默认配置；候选有收益可保留，默认关路径仍可用。

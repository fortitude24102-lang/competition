## 实现及边界

只在gpu.c/h增加编译期开关GPU_SUBMIT_SHADOW，默认0。设置1后，每个独占gpu_device保存8个实际已写入的描述字，首次强制全写，以后只写变化字段；tag、CONTROL和两次I/O屏障不省。PRESENT始终完整写8字段＋tag/CONTROL，保持纯CPU对比的翻页原路径。操作切换不省必要的零值写入，参数验证与既有单次校验、队列信用、tag、错误和超时流程不变。

必须保持单生产者；设备复位或绕过驱动写命令寄存器后先gpu_init重新同步。全部编译单元必须用同一GPU_SUBMIT_SHADOW宏。宏0不增加gpu_device字段，正常互动固件BIN与原合格版逐字节一致，SHA256 ec966d397e4d085e7fb40eac59a17eb865cd948396bbe1647256343830c0613c。没有CPU绘图、游戏、素材、RTL、频率、AXI事务或图集Cache变化；保留候选仅用于复现，不在发布/正常默认路径启用。

test_submit_shadow.c链接真实gpu.c及R7构建器，仅替换外部APB访问，在每次CONTROL提交边界检查全部8字、tag、提交和屏障。预期字段直接按合同独立组合，不调用驱动打包助手来产生答案。首次旧驱动RED：第二条仅目的地址变化的Key仍写10次，预期3次。实现后GREEN；随后PRESENT原路径10次写预算RED，再保持全写后GREEN。

## 排除诊断入口布局干扰

首轮旧/新/旧512工作均值21.762→22.240→21.764ms，但旧路径命令构建也异常达到8.026ms，不能直接与之前QoS的3.184ms比较。检查ELF符号发现，初版无条件扩大gpu_device后GCC将诊断continuous内联进main，构建函数地址也改变；原QoS/冻结旧版仍为独立continuous.constprop.0。改成候选字段只在宏1存在，旧-r2重新测得构建3.180ms、工作17.118ms，且默认正常BIN恢复原哈希。

为避免两个候选选择不同的内联策略，仅把诊断continuous标为noinline，旧/新共同使用，main/build_frame位置相同。以下取舍使用此最终r3组。首轮失败、旧-r2和未上板候选的原文件全部保留，不删除不利结果。此证据证实构建策略变化是重要干扰，不提供CPU Cache miss计数，不能把具体缓存冲突机制写成已证实根因；没有借此修改或优化正式CPU渲染。

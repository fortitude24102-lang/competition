## 背景和HUD

512隔离背景三次壁钟7.606 / 7.579 / 6.943 ms，每次读/写各898560 B，under0；隔离按序Sprite壁钟4.851 / 5.109 / 5.177 ms，busy3.922 / 4.271 / 4.284 ms。背景仍是最大单项：正常512场景平均DDR读取919289 B、写入951204 B，背景占读取约97.7%、写入约94.5%。这些比例是场景计数，不含HUD，不是DDR总利用率。

512正常HUD Cache更新221 us、HUD Copy619 us；probe=1为196 / 1154 us。低档HUD Copy约1.20 ms，同样说明突发/扫描相位会影响测量；不能把一次619 us称为新HUD优化。512正常PRESENT等待15.918 ms，是错过刷新后的等待结果，不把删除同步当作提速。

此前背景恢复在旧硬件低档有净余量收益，但512规划/碎片命令抵消搬运收益，最佳仍约30.5 FPS；本轮未重新跑该候选，不能把旧恢复系数或其收益直接叠加到本表。

## 第10～11天决定与退出条件

三项计划门槛本轮均满足：512不达60；诊断构建+非阻塞提交>1 ms；后端平均busy没有单独耗尽帧预算。因此选择最多16模板、16 B实例的受限APB流前端，复用原有有序队列及Key/Alpha/Copy后端，采用冻结0400窗口合同。Sapphire仍负责输入、逻辑、碰撞、裁剪、实例生成和顺序；硬件只展开描述，不把逻辑搬到PC或GPU。

执行先离线逐字段比较实例展开与旧命令，并测**紧凑构建+提交整体净成本**，不能仍完整构建旧流再额外转换而宣称消除了构建。先覆盖越界、模板忙写拒绝、背压、混合批次、tag和部分执行错误。资源XLR96.22%、RAM84.77%已经接近上限，必须先综合资源/时序，不因寄存器少就假定放得下。

原型只在正常整帧P95/最大和miss、下溢/错误优于同版旧路径且100 MHz STA合格时接入；没有净收益或放不下即退出，保留旧ABI，不建空壳。部分Alpha已执行后不可从头重放旧批；使目标历史失效后完整重建。后端硬件局部优化仍可作为退出后的方向，但不同时引入完整CDMA/多ID/Tile合成器。

本轮CPU基础绘制不改也不重复完整600tick慢回放；同位流前一轮已测CPU约2.8 FPS，仅作为历史记录，不能填入本次冷启动的有效CPU成绩。恢复交互固件后CPU成绩应保持未测/不可用，等用户按C完成比较后更新。

收尾已JTAG恢复相同r3 BIT和原交互BIN，资源加载result0/retry0，GPU稳态60.1 FPS、under/miss0。恢复捕获脚本停止模式误写`V3_FPS`而实际输出`V3_PERF`，75秒后超时；该失败保留，不冒充恢复脚本通过。随后独立真实控制脚本退出0，ACK、右移/上移和超时松键通过；网关用新HELLO/ACK恢复同build序号基线，最终遥测真实且未过期，CPU显示不可用。没有重跑600tick比较，没有烧录进程残留。

# 半字相位颜色键控 DMA（2026-09-28，本地候选）

目标：保持 R6 弹幕场景、CPU 基础对照、素材、命令顺序、100 MHz 和
软件寄存器接口不变，只提高 GPU 对错位和奇数宽度 Sprite 的事务合并覆盖率。
不实施图集缓存或脏块背景恢复；这些是后续独立设计。

## 实现与边界

- 复用 `AxiReadEngine` / `AxiWriteEngine` 的 4 KiB、256 beat 分割和响应检查。
- 完全对齐、偶数宽度 Copy / Key 保留原直通，不增加重排延迟。
- 非重叠 Key 通过 `Rgb565WordAligner` 的 4 像素移位/携带寄存器重排两个
  RGB565 像素，支持源、目的分别位于字低/高半字及独立步长相位变化。
- 首尾有效 lane 与透明色比较共同形成 WSTRB。全透明字保持 burst beat、
  WSTRB=0，不读背景。行末单像素在已读数据中刷新，不等待不存在的后继 beat。
- 处理像素计数为有效 lane 数（包括透明像素），写字节只计真实置位的 WSTRB。
- 对扩展条件新增保守的整矩形地址区间重叠判断；重叠命令走原像素路径。
  原对齐 Key 路径的历史行为不在此轮修改范围。
- 完成必须同时等待读数据耗尽和最后 B 响应；错误在当前行排空后报告，
  后续命令重新初始化状态。

参考 [AXI CDMA](https://github.com/alexforencich/verilog-axi/blob/master/rtl/axi_cdma.v)
的移位/携带及边界掩码思路，没有引入外部 DMA 核或复制其 RTL。
当前贡献是针对 RGB565 透明精灵的工程适配，不宣称移位算法全球首创。

## 验证记录

`WordKeyDmaSpec` 首次在旧 RTL 上按预期失败：错位 Key 仍出现
`pixelRequest`，不能绕过阻塞的像素通路。新实现首次 30 个参数案例
通过（宽度 1/2/3/8/11/12/513；四种地址相位；透明/保护区；随机停顿；
跨 4 KiB/256 beat；延迟 B；读写错误及后续命令）。
随后按静态审查补入：源/目的独立步长、后续源行与前一目的行重叠回退、
真实 RenderEngine 的 6 像素/16 B 读/6 B 写计数断言。

完整 GPU 回归一次 **63/63** 通过，11 个 suite；生成 RTL 成功。
此回归启动后补入的测试再定向跑最新 `WordKeyDmaSpec`，**3/3** 通过。
没有重跑整套长回归。审查的重叠/独立步长覆盖缺口已补齐，未发现功能阻塞。
Efinity `map/interface/pnr/pgm` 全部 PASS。100 MHz 核心 setup/hold
余量为 1.792/0.026 ns；400 MHz SDRAM setup/hold 为 0.431/0.068 ns。
历史 `SoftwareDriverSpec` / `PangoBringupSpec`
异常仍保留，不能把 GPU 专项回归写成全项目通过。

上板短检查 `scripts/build-board-hud-dma-test.ps1 -Test key` 只构建、不烧录；
29 个案例使用实际 DDR 检查全部目标、透明像素及保护区，并核对计数器。
五档性能和普通 CPU/GPU 对比继续用上一轮完全同一份固件，避免软件变化
污染硬件对比。只临时 JTAG 加载，不写 Flash、不覆盖 `release/v2/`。

实际 29/29 案例通过，覆盖宽度 1/2/3/8/11/12/513、四种地址相位、
奇偶宽度、跨 4 KiB/256 beat 和全透明行；硬件错误 0。

固定五档探针的 60 个阶段与上一候选逐项核对：命令数、处理像素、
读写字节和 15 个场景的可见数/Alpha 数完全相同，全部下溢为 0。

普通 64 档使用完全相同的固件：CPU 场景 331.980～333.605 ms、
2.5～2.6 FPS；GPU 场景 10.214～10.231 ms，比上一候选对应九个窗口

因此本轮接受的是 Key/FULL 局部吞吐继续提升，不是整帧达标。

综合相对上一轮：LUT 28,835→29,274、FF 27,238→27,354，
DSP48 10→14，DSP24=6、RAM10=141 不变。
新增 DSP 用于重叠区间乘法判断，不是 Alpha 像素吞吐升级。
不能仅凭功能测试宣称没有面积代价。整体 FPS 必须包含 HUD 和 PRESENT，
阶段耗时下降不等于稳定 60 FPS。

# V3 第10～11天：紧凑实例前端候选（2026-10-06）

本阶段执行[第9天门槛结论](v3_decision_day9.md)，不是换CPU或美化画面。新增部分默认关闭，未替换 `generated/efinix_gpu`、板级正式源清单或 `release/v2`。仅在离线等价、资源、最终时序和同帧板测净收益全部通过后，才允许讨论默认接入。

## 架构与兼容范围

Sapphire直接生成16 B实例 → APB四字影子寄存器/提交 → 16个只读模板展开 → 原有16项命令队列 → 原Copy/Key/Alpha后端 → 原DDR仲裁/双缓冲/HDMI。不存在新DDR端口或第二个独立渲染队列。背景Copy也在同一批中，保持原顺序，不额外添加Copy/精灵之间的等待栅栏。

本候选仅实现冻结R7自动回放的GPU构建器，12个模板覆盖背景、共享光晕、六弹形、玩家和三个发射器。CPU构建/绘制、游戏状态更新、互动固件、网络模块和官方Demo文件不变；手动互动的kind=3友方弹路径仍走原构建器，不能把自动回放等价视为互动接入完成。

生成时必须显式使用 `--instances`；Top与生成器默认均关闭该前端。与合格r3对照的候选同时选择 `--legacy-copy`，不混入已被拒绝的Copy通路。

## APB接口补充

地址均为GPU局部、32-bit对齐；旧寄存器地址/ID保持不变。原STATUS新增bit14表示编译了实例前端。驱动先读这个安全的旧地址；未置位时不访问新窗口，使用旧命令提交。这样避免在旧位流上读0400产生PSLVERR。此规则补充固定架构接口中原“ID探测”的安全前提。

| 地址 | 名称 | 行为 |
|---|---|---|
| 0400 | ID | 只读INS1=`0x494e5331` |
| 0404 | STATUS | bit0批活动；bit1活动且暂存槽可接收、无错误；bit2后端/缓存/暂存全空闲；bit3前端错误；[15:8]错误码 |
| 0408 | CONTROL | 写1 BEGIN，仅全局空闲且无硬件错误；写2 END，仅批活动且排空；写4清前端错误，仅空闲/非活动 |
| 040c | TEMPLATE_INDEX | 写0～15，仅空闲/非活动；选择时使该模板失效并清七字段完成掩码 |
| 0410～0428 | 模板七字段 | op/src_base/src_stride/dst_stride/width_max/height_max/key；七项均重新写入后模板才有效 |
| 0430～043c | 实例四字段 | header/dst_addr/src_offset/width-height；仅活动/无错误时可写 |
| 0440 | INSTANCE_COMMIT | 写1；四项均新写、暂存空闲、模板/描述合法且无错误才接受；接受后清四字段掩码 |
| 0444 | BATCH_TAG | 写首tag，仅空闲/非活动、值≤65535；读最近接受的tag；每接受一次递增，16-bit回绕 |

header为template_id[7:0]/flags[15:8]/alpha[23:16]/reserved[31:24]。仅Alpha模板flags=1，其余=0；非Alpha的alpha必须为0。当前模板只允许Copy/Key/Alpha。硬件核对尺寸、线性二维跨度是否越过模板背后分配区间、地址溢出、DDR窗口、对齐/步长与Copy/Alpha重叠。CPU已按R7原规则裁剪；这不是接受任意图像布局的通用资源重映射器。

同一批与旧SUBMIT互斥，旧纹理缓存加载/失效也被空闲条件阻止。新实例不得绕过已有队列顺序。暂存命令在背压时保持全部字段不变；结束/编辑模板不能丢掉已接受命令。

遇到部分执行、硬件错误或超时立即返回，不自动从头改走旧通路，避免再次执行Alpha。驱动保留活动状态以阻止盲目重试；需要调用方完成显式安全恢复（必要时完整GPU复位）并重建目标帧。正常固件未接入本候选，因此尚未新增自动恢复流程。

调用者为单一GPU所有者，传入有效的16槽模板数组，在批次期间不得修改该数组。内置R7资源与目标互不重叠；通用扩展器允许的同面Alpha/重叠Key不属于本原型兼容承诺，因为旧C驱动回退会拒绝这些重叠。拓展到其他场景前需统一这项约束。

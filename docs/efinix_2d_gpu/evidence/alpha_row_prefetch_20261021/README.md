# Alpha跨行读预取（2026-10-21，显式候选）

本轮只改GPU硬件，起点3e53d32；实现56fbafd。旧四笔写BIT作为对照，CPU基础绘图、官方Sapphire/100MHz、网口职责、软件命令容量与游戏负载不变。未推送main、未写Flash、未替换release。

## 改了什么，为什么不加新DMA

上一轮1040固定诊断中Alpha约2.21ms。原Alpha已有前景/背景两个读通路及各33字FIFO，也能在64像素块之间预取，但每行结束仍等待上一行写响应才读下一行。因此复用已有缓存、FIFO和DSP，让符合条件的下一行前景/背景读取与上一行最终B响应重叠；**写通路仍只允许一笔在途**，不加RAM、CDMA或软件ABI。

新尾参数`enableAlphaRowPrefetch:Boolean=false`，CLI`--alpha-row-prefetch`要求`--alpha-pipeline`。仅Alpha、宽1..64、高>1、源/目的整体边界不重叠时启用；宽图和原地Alpha回旧路径。出错后停止尚未接受的下一行写请求，但排空已承诺的读写；最后清掉被放弃的预取对齐状态，后继Alpha不能读到旧像素。最后一行仍等真实写退休后才完成命令。

借鉴[verilog-axi](https://github.com/alexforencich/verilog-axi)独立读写/FIFO承接完整事务的方法，更直接复用本工程原有块间预取；未引入第三方代码或新依赖，不把跨行预取本身宣传为首创算法。本轮特色是利用已有存储、保留单写退休和错误排空的小范围架构改动。

## 后续瓶颈与边界

固定1040诊断现在背景约5.55ms、Alpha约1.89ms、Key约1.64ms。Alpha读写重叠有实测收益，但仍有读空隙、逐Sprite命令退休及背景大块搬运；不能仅凭等待计数就决定扩Cache或继续加写信用。下一轮优先对高活动数量下的背景通路与跨Sprite调度做独立时间线/事务对照，再选改动，不把CPU绘图当优化对象。

本轮还观察到搜索效率问题：长窗失败后原程序把low清0，重新用600帧短窗二分，可能再次逼近几乎相同的短窗边界，随后长窗再失败。它没有伪造通过，但在900秒内可能得不到任何最终确认。后续应增加失败长窗终止计数、复用长窗失败边界并改进搜索预算/保守候选选择；**资格门槛和实际负载不降低**。这是后续软件测量策略，不算本轮硬件提速或已完成修复。

普通1024仍有19ms以上最坏work，完整帧包含逻辑多次推进/命令构建的长尾；本轮硬件优化没有证明这些已消除。32位AXI、60Hz显示、现有内存布局不改。独立缩放/灰度、手动移动/死亡、CPU慢比较中途重选限制、30分钟实机耐久、所有开关组合和历史SoC异常未在本轮补验。

## 机制与功能检查

借鉴[verilog-axi axi_fifo_rd](https://github.com/alexforencich/verilog-axi/blob/master/rtl/axi_fifo_rd.v)的FIFO_DELAY整burst容量预留机制，使用本工程既有256项返回队列，没有引入第三方IP或增加RAM。仍只允许一条物理读事务，当前事务R全部排空后才选择下一条；AR等待期间旧队列占用只能下降，因此预留不会被另一条返回流抢走。

len+1用9位、与count求和用10位，覆盖256拍最大突发且不回绕；不改ID/resp/last、原序、显示紧急优先、已呈现VALID保持和复位协议。新用例先在原源码等待残留队列排空时失败，后验证1+255项恰满、满时阻止新读、Scanout仍可前进、释放1项后接受1项、错误/ID/last逐项有序排空。

首次全套因测试ID77超出4位而失败，已改为合法13并匹配请求/返回；保留该失败，修正后9项通过。另15项四写信用、顶层、宽口MUX和配置集成通过并生成候选。独立审查未发现未解决RTL缺陷；审查指出的物理身份缺口另按下节修复。

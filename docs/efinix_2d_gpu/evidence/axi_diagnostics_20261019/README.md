Key的物理读每次4160拍=16640B，恰为实例描述符，贴图仍读Cache133504B；不是贴图DDR miss导致。W拍随半字相位变化（33376..38920），即使WSTRB为0也占拍；有效写63916..63940B不能替代总线拍。8328行经4KiB拆分后每阶段8372..8387个AW/B，均完全平衡。Key写背压0，而B等待占约42%，支持先做**Key专用两笔在途写**，连同行调度和仲裁B-owner队列一起改。不能把1.47ms都预先算成可得收益，显示紧急状态仍阻挡新AW。

背景B等待仅0.235ms，单改背景CDMA的这一机制上限较小；其W背压、读供应和显示仲裁需要另行研究。本轮不改显示保护阈值、不以牺牲下溢换吞吐。

## 对照和诊断边界

先在诊断BIT运行原保存r3分段BIN，再重载同BIT运行计数固件；两组各24阶段，命令数、read/effective-write/cache字节逐项一致，6个fixture CRC沿用固定输入。全部阶段新增下溢0、STOP result0/hardware0；实际R拍×4等于原读取字节，AW/B数量相等。所有64bit elapsed远小于40秒，未发生32bit诊断计数绕回。

诊断固件增加APB启停和串口字段，改变阶段间扫描相位；1040完整场景原BIN均值11.37713ms、诊断BIN11.06487ms，**这不是提速**。不将旧BIN/诊断BIN差值当收益，不拿分段求和推游戏FPS。下一候选A/B必须用相同诊断BIN和同一普通游戏BIN分别比较。

## 背景恢复的离线筛查

按当前`pc_build`和真实初始化/移动方程在内存中计算保守包围盒覆盖，未读取透明纹理，不是实板写入测量。1040、tick11/22/33的精确包围盒并集分别72938/72600/68052像素；16×16网格覆盖约72..74%ROI，展开为2576..4768个真实连续显存区间，不能把网格扫描的161..298段误当长DMA。

32B细块只有35..40%覆盖，但产生3470..5500区间。按间隔≤256B合并后：

源/目的均4KiB对齐加ROI偏移0x21c00，因此两方向切分一致。两组已经恢复约88%背景且Burst比全Copy更多；即使去掉软件规划，硬件维护/碎片成本仍在。**暂不实现新的背景恢复子系统**，先解决短事务等待。DMA、Cache、脏区域本身不是首创。

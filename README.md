## 回顾赛题：已实现什么，还缺什么

依据用户提供的 2026 易灵思选题原文。硬件存在、离线正确、板上运行和长期达标是不同层次。

| 赛题要求 | V2 阶段结论 | 证据或限制 |
|---|---|---|
| RISC-V 命令包含操作、源/目的地址、宽/高；硬件 Copy、Fill | 已实现 | C 驱动、APB 影子寄存器、16 项命令队列、验证器和 DenseBlit |
| 最低 640×480、60 Hz VGA/HDMI 时序，显存输出 | 已实现显示链路 | V1 为 640×480 居中放大；V2 为 960×540 RGB565、2×全屏 1920×1080 HDMI。显示 60 Hz 不代表游戏每档 60 FPS |
| 系统总线直接访存，合理使用 Burst/FIFO | 已实现 | AXI32、最长 256 beat、4 KiB 边界切分、显示 FIFO、渲染响应 FIFO；当前仍有事务串行瓶颈 |
| C 寄存器驱动、双缓冲避免撕裂 | 已实现机制并板测运行 | vblank PRESENT、A/B 缓冲；历史热重载下溢未定位，不能称所有启动/恢复方式均稳定 |
| 屏幕实时显示纯 CPU 与 GPU FPS 差异 | 已补齐 V1 缺口 | 同状态分时回放，屏幕保留最近有效的两组成绩；CPU 不新增优化、不接 GPU 绘制、不人为降速 |

| 颜色键透明去背 | 已实现 | 品红键；字突发/WSTRB、奇偶宽度与半字相位支持，透明像素不覆盖背景 |

## 研发思路与架构变迁

研发始终沿“官方可靠底座 → 可验证 BitBlt → 真实异构闭环 → 计数定位瓶颈 → 定向优化”推进，不围绕换 CPU 或画面美化转移比赛重点。

| 阶段 | 架构变化与原因 | 形成的特色/边界 |
|---|---|---|
| 官方 Demo 复用 | 采用 Sapphire+DDR3，复用 HDMI；官方文件只读复制到 vendor 并登记哈希 | 避免重做 CPU、DDR PHY 和视频接口；团队分工为 Chisel/Verilog/C |
| V1 基线，9/17 源码冻结 | APB → 验证器/队列 → Fill/Copy/Key/Alpha/Sparse → AXI → 双缓冲 → HDMI；640×480 居中输出 | 带 tag 的异步批量提交、错误反馈、Sparse token、自适应 DDR QoS、性能快照；当时缺屏显 CPU/GPU 对比和实测稳定极限 |
| V2 功能升级，9/26 首轮板测 | 增加官方 GE/MAC、资源包保护/CDC、Asset DMA 和 Sapphire 资源客户端；改为 960×540 全屏 | PC 是网络资源盘；RISC-V 主动请求并完整校验；屏显 CPU/GPU 实测对比，不再只报软件周期 |
| V2 第一轮性能改进，9/27 | 先测出 Alpha 1–2 像素事务的地址/响应开销，再改 64 像素分块；对齐 Copy 走 32-bit 字直通 | 优先提高事务效率而非盲目加乘法器；旧场景 Copy 约 22→8.2 ms，但显示下溢记录使候选不能直接封版 |
| V2 小 Sprite 通路，9/28 | 接入 R6 弹幕；Key 使用 WSTRB 字突发，增加半字移位/首尾 lane 掩码；再增加 4 KiB 显式纹理 Cache | 针对反复使用的小图集降低 DDR 事务；512 档同探针 Key 约 7.3–8.0→2.62–2.80 ms，CPU 路径不变 |
| V2 帧预算优化，9/29–9/30 | 不再 Copy 会被 HUD 覆盖的 72 行；合入 R7；GPU HUD 只复制变化字形 | 每帧背景少读/少写各 138,240 B；同背景和同 Sprite，不靠减分辨率/对象/Alpha 提速；CPU HUD 仍完整重建 |
| V2 阶段收尾，9/30 | 分离命令构建、队列压力、硬件 busy、背景搬运与 PRESENT 节拍 | 瓶颈已转为背景 Copy 和高档位命令前端；下一阶段以测量选架构，而非继续无限加 Cache |

上表日期对应阶段记录，Git 合入日期可能稍晚；跨场景数据仅解释过程，不作统一加速比。

## 当前系统分工

| 组件 | 职责 | 不承担的工作 |
|---|---|---|
| PC Asset Server | 按资源 ID/偏移返回文件字节 | 不运行游戏逻辑、不决定 Sprite 位置、不生成 GPU 命令、不合成每帧图像 |
| 官方 Sapphire RISC-V（100 MHz） | 请求/重试/完整 CRC、资源管理、游戏更新/碰撞、构建及提交 GPU 命令、CPU 基础绘制对照 | 不被架空为只启动 FPGA 的壳；不为比较人为降速 |
| GE 接收保护 + Asset DMA | 校验包边界/会话、跨域受保护载荷、写 DDR 资源区、反馈状态 | 不允许尚未完整校验资源成为可见素材 |
| AetherGX（100 MHz） | APB 命令合同、按序执行、Fill/Copy/Key/Alpha/Sparse、4 KiB 纹理 Cache、计数/错误 | 不替代 RISC-V 决定玩法；当前没有新 CDMA 或 Tile 合成器 |
| DDR 仲裁 + Scanout + HDMI | 资源/渲染/扫描共享 DDR，水位 QoS、响应缓冲、A/B 显存、vblank 翻页、1080p 输出 | 不靠关闭扫描、丢 Alpha 或撕裂交换取得 FPS |

DDR3 为 MT41J128M16JT-125；软件合法 GPU 地址窗口为 0x02000000～0x10000000（右端不含），不等于整片 DDR 都可自由分配。A/B 显存为 0x02000000/0x02200000；图集、背景和 HUD 使用独立资源区。每个新增/修改的 .v 文件只含一个模块，生成 RTL 使用拆分模块。

## 设计特色：哪些是复用，哪些是本项目工作

官方 CPU、DDR3 控制器/PHY、HDMI/GE 底座属于复用，不作为自研成果。自研/适配工作主要为：

1. 软硬合同闭环：验证器、16 项有序队列、tag/错误完成、C 异步驱动、RGB565 黄金模型、DDR 像素比较和性能快照。
2. 二维图层通路：Alpha 分块读背景、颜色键 WSTRB 字突发、错位/奇数宽边界处理，以及 Sparse 行内跳过/实色 token。
3. 显示与渲染共存：显示 FIFO 水位迟滞、渲染防饿死和整突发响应缓冲，优化必须保持零下溢。
4. 显式资源局部性：Sapphire 预载小图集至 4 KiB GPU Cache；GPU 特有 HUD 字形缓存与遮挡背景裁剪，不改变 CPU 基础实现。
5. 可核验的异构演示：PC 存资源、RISC-V 执行逻辑、FPGA 渲染；CPU/GPU 同状态回放，报告真实时间、工作量、错误和下溢。

突发、FIFO、Cache、脏区域和 DMA 都不是本项目首创。下一阶段可争取的创新是“针对小 Sprite 工作量、双缓冲历史与显示截止时间的组合设计”，必须以同画面正确性和实测收益支撑。

## 保留问题与封版条件

- 固件热重载曾出现 80,700 次下溢，旧候选曾出现 242,100 次；完整复位后没有复现不等于根因修复。封版需冷启动/复位/重载与耐久验证。
- SoftwareDriverSpec、PangoBringupSpec 两项历史 SoC 固件基线异常保留，不能宣称全项目回归通过。
- 真实玩家输入未实现。9/30 静态检查还发现：当前工程及已板测候选将 soc_gpio[0:1] 接到 LED0/1 的 GPIOR_27/_24，而 main 以其读取 KEY1/KEY2；手册实际按键为 GPIOR_22/_21。因此不能把软件提示当作实体按键验收，需要修外围映射或先用现有 UART。
- 网络首轮及正常复位记录有零重试证据；服务器未启动、PHY 未稳定会超时并转本地素材。回退必须显示失败状态，不计作网络加载成功；不是“千兆接口即可每帧下载素材”。
- 尚需同版逐档极限、断网继续、输入异常、至少 30 分钟耐久及最终位流/固件/素材哈希清单。当前操作仍只用 JTAG，未烧写 Flash。
